What the field looks like

  • Beyond the Chatbot is the crowded room. Because the Nemotron track stacks with everything, roughly half the field enters it. The entries with real evidence that Nemotron does more than chat are Dryrun (deterministic capability search after extraction, live URL, tests), Nemotron as Verifier (43-case eval with a coverage-versus-recall curve), Trouvé (rules-plus-model scoring with honest evals) and Heard! (a written Nemotron eval).
  • Total score and Wow diverge, and that is the point. Games and hardware projects (Explain Yourself, Light Wizard Money Gang, Fernvale GBA, Pickleball On The Go, Mesh Mail, Canopy Co.) post middling totals but sit at the top of the predicted judge ranges. Dense finance and document tools (RealityCheck, BankManager, Panther Post) do the opposite.
  • Mock-by-default is the norm. Around a third of the scored projects ship a labelled fixture, stub or 'offline preview' path as the documented demo default. Live judges should ask 'is this live right now?' before crediting an AI step.
  • Agent scaffolding is everywhere. CLAUDE.md, AGENTS.md, handoff briefs and PRDs appear in well over a third of repositories; in RealityCheck, BankManager, OmniSight and HelloWord the planning documents outweigh the code. Completeness was scored on the wired code path, never on the plan.
  • Hygiene slips worth fixing before the deadline. Live keys or tokens are committed in SplitSense (NVIDIA), PennyWise (Presage), Panther Post (ElevenLabs, plus recipient and staff PII), Bad Faith (Supabase auth tokens) and GutGuide (ElevenLabs, in history); Night Shift committed a full .venv.
  • Provenance gaps. Several repositories arrive as one or two bulk commits with no development history (RealityCheck, Fernvale GBA, PGH Transit, Noise2Node, Stockd's first 7k lines). Meal Plan Tracker landed eight feature commits before the 11:00 start and Heard! ported 3,867 lines from a prior build; both are reflected in the objective fresh-code score.
  • Finance dominates the themes. A dozen projects are fintech (fraud desks, banking agents, budgeting, valuation, credit), followed by games, campus utilities and voice products. Presage and Solana drew almost nothing: one real Presage integration (Canopy Co.) and no Solana build was found.

Method and rubric

Every scored repository was cloned locally at the snapshot time and analysed two ways. A script computed the objective score (40 points) from git history and the file tree. Reviewers read the README and core source of each project to produce the subjective score (60 points), then the lead judge re-calibrated all scores on a single scale. A separate Wow index (0–10) models what a human judge sees in a 3-minute live demo. Submission materials (video, slides, Devpost fields, team info) are deliberately not scored: the deadline had not passed at snapshot time.

Objective score · 40 pts · machine-computed

ComponentPtsHow it is computed
O1 Code substance10Non-blank lines of source, excluding vendored directories, lockfiles, minified bundles, data/asset files and docs. Log-scaled: 100 → 1.5, 1k → 5, 3k → 7, 8k → 8.5, 15k+ → 10.
O2 Build effort10Half from commits inside the hacking window (Sat 11:00 EDT onward; 5 → 3, 30 → 7, 100+ → 10), half from distinct hours with commits (10 → 5, 24 → 10).
O3 Team collaboration5Distinct human commit authors (1 → 2, 2 → 3, 3 → 4, 4+ → 4.5) plus 0.5 when no author holds more than 60% of commits.
O4 Runnability & hygiene10Build manifest 2 · README with run instructions 2 · .gitignore 1 · no vendored deps or secrets/.env committed 2 · tests 1 · CI/deploy config 1 · env example 1.
O5 Fresh-code integrity5Share of source added by commits inside the window versus total source (≥95% → 5, ≥80% → 4, ≥60% → 3, ≥40% → 2, ≥20% → 1).

Subjective score · 60 pts · reviewed, then calibrated

ComponentPtsAnchors
S1 Idea novelty120–3 seen many times · 4–6 common category with one twist · 7–9 uncommon problem or new mechanism · 10–12 a category judges have never seen.
S2 Need / problem validity100–2 no clear user · 3–5 plausible but generic · 6–8 specific user with real pain · 9–10 urgent and credible with evidence.
S3 Track fit80–2 no track or superficial sponsor use · 3–5 partial fit · 6–7 strong fit to the track's stated criteria · 8 nails one track and credibly stacks another.
S4 Completeness150–3 skeleton · 4–7 core loop not wired or mostly mocked · 8–11 works end to end with rough edges or fixtures · 12–15 polished, real data path, error handling, eval or tests.
S5 Demo appeal150–3 CLI/notebook · 4–7 basic UI · 8–11 attractive UI or an interactive/physical element · 12–15 visually striking, something judges can touch, hear or play.

Wow index and the human-judge rank range

A judge with three minutes never reads architecture, counts lines or weighs technical depth. The Wow index scores only what lands in those minutes: a new arena nobody expected, an unexpected twist on something everyone builds, or something visceral: fun to play, beautiful, physical, audible. 0–2 nothing · 3–4 mild interest · 5–6 one clear "huh, neat" · 7–8 one strong wow · 9–10 several wows.

The human-judge rank range shown per track re-orders the field by a demo-day model (60% Wow, 25% demo appeal, 15% novelty) and widens it by one place above and one to two places below to reflect judge variance and demo luck. It is a prediction of where live judges would land, not the score-based rank.

Coverage and limits

  • Discovery: GitHub repository search for "steelhacks", "steel hacks", "steelhacks xiii" and "steelhacks 2026" restricted to repositories pushed after 18 Sep 2026 (all result pages), the steelhacks and steelhacksxiii topics, and web search. Repositories that never mention SteelHacks are invisible to this method.
  • The organizer sites (steelhacks.org, the Devpost page) were unreachable from this sandbox; track definitions were reconstructed from organizer wording quoted inside participants' planning documents and from search snippets.
  • Scores reflect the repository state at 2026-09-20 12:30 UTC (08:30 EDT), roughly two and a half hours before the submission deadline. Teams were still pushing.
  • Nothing was executed. "Works end to end" means the code path is wired in source, not that it was run.
